The documents say what the checks do, and no more. The README now opens with a table of where each gate runs and what it cannot see, and every promise in README, EXCEPTIONS, TOOLKIT, SECURITY and CONTRIBUTING names its check, test or workflow. Claims that had no gate are narrowed or stated as limits: the `required` job blocks a merge only once a repository's ruleset names it (`init --github` writes it; the current consumers have not added it yet); a fix in a reusable workflow reaches a consumer when it re-pins the SHA, never on its own; the release `build` job runs the package's `verify` script, so only the `publish` job runs no repository code; the 0.17.0 release path has not yet produced a real release; the paired benchmark overhead gate ships in the next release and reaches a consumer when it re-pins; the `Commits` check rejects a `Co-Authored-By` trailer. The consumer templates get the same treatment: `contract.yml`, `release.yml` and the pin-sync workflow comments describe the ruleset and the `PIN_SYNC_TOKEN` as they are, SUPPORT directs readers to Issues (the scaffold does not enable Discussions), RELEASING names the contract-run requirement in the build job, and the benchmark guides drop vague wording.
